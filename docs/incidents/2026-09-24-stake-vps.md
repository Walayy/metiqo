# Stake sur le VPS : challenge du 24 septembre 2026

## Faits vérifiés

- Le worker Docker `metiquo-stack-stake-worker-1` est sain. Chrome Stable
  `154.0.8037.57` démarre sous Xvfb ; le profil dédié
  `/data/browser/stake` appartient à l'utilisateur du conteneur.
- Le code de `stake_browser.py` sur le VPS était identique à celui du dépôt
  local au moment du contrôle. L'adresse IPv4 sortante observée depuis le
  conteneur est `195.35.0.154`.
- L'horloge du serveur est synchronisée par NTP. Dans le conteneur, aucune
  variable de proxy n'est définie ; Chrome garde ses réglages par défaut pour
  les cookies et JavaScript.
- Le 24 septembre à **15:02:34 UTC** (17:02:34 à Paris), le document principal
  `https://stake.bet/fr/sports/esports` a répondu HTTP `403` avec
  `cf-mitigated: challenge`. L'historique du profil Chrome donne pour cette
  visite le titre exact **« Just a moment... »**. Aucun match ni marché n'a
  été atteint.
- La ligne `collector_state` de Stake conservait `blockedReason: challenge`,
  `requestCount: 8` et `blockedUntil: 1790265756.3353615`, soit
  **16:02:36 UTC** (18:02:36 à Paris). Le journal d'ingestion ne contenait pas
  le Ray ID. L'entrée de cache du profil Chrome pour cette URL, datée de
  **15:02:34 UTC** et contenant le statut HTTP 403, donne
  **`a402abbf5f852068-CDG`**. L'identifiant provient de cette entrée locale,
  et non du journal d'ingestion.

Selon [Cloudflare](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/),
`cf-mitigated: challenge` identifie une réponse de challenge à la place du
document attendu. Cela ne révèle pas la règle déclenchée : IP, navigateur,
rythme et autres motifs restent des hypothèses. Un navigateur qui fonctionne
sur Windows ne prouve donc pas que le VPS sera accepté. Cloudflare précise
également que les [navigateurs automatisés ne sont pas pris en charge pour
résoudre les challenges de production](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/).

Le [forum Stake](https://stakecommunity.com/topic/120705-constant-cloudflare-checks/)
conseille pour un navigateur humain de vérifier sa version, les cookies,
JavaScript, l'horloge et le réseau. Ces points ne montrent aucune anomalie
évidente sur ce VPS. Les témoignages GitHub et Reddit sur les VPS proposent
souvent de changer d'IP ou de transférer un cookie de passage ; ils ne
constituent ni une preuve de la cause de ce refus, ni une solution fiable et
autorisée pour Metiquo.

Le collecteur arrêtait auparavant la navigation dès que « Just a moment... »
restait visible après deux secondes. Selon la [documentation Cloudflare sur
les challenges non interactifs](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/),
un navigateur peut normalement terminer ce chargement en quelques secondes.
Une correction laisse donc la **même navigation** se terminer passivement
pendant au plus le délai de lecture configuré, sans clic ni nouvelle requête
pilotée par le collecteur. Le test local dans le Chrome du VPS a confirmé que
le code accepte une page dont le titre change après 3,2 secondes et arrête
une page de protection qui persiste après 7,2 secondes. Il ne teste pas l'accès
à Stake.

À la demande de l'exploitant, l'ancien délai en base a été levé pour un passage
réel immédiat. Le **24 septembre 2026 à 15:43:33 UTC** (17:43:33 à Paris), la
première navigation vers la même URL a de nouveau reçu **HTTP 403** avec
`cf-mitigated: challenge` ; le titre était **« Just a moment... »** et le
nouveau Ray ID **`a402e7caa880b940-CDG`**. Après 48 secondes, le passage
`c2c88221-ed49-4834-9291-5e881857c3fa` a échoué avec zéro rencontre et zéro
cote. Ce résultat confirme que l'attente passive ne suffit pas sur cette IP
à cette date. Il ne révèle toujours pas la règle Cloudflare.

## Suite autorisée et vérifiable

Le worker conserve le dernier état valide et ne publie aucune cote nouvelle.
Le délai local fixe d'une heure sur le VPS est retiré à la demande de
l'exploitant : un challenge termine le passage, et seul le prochain cron ou un
lancement manuel peut réessayer. Un `Retry-After` explicite et le budget
restent respectés. Le journal d'ingestion conserve le Ray ID et le titre court
de la page, sans corps HTML, cookie ni jeton. Transmettre à Stake l'URL,
l'heure UTC, l'IP sortante, le code HTTP, le Ray ID et le titre. Le [Ray ID](https://developers.cloudflare.com/fundamentals/reference/cloudflare-ray-id/)
aide le propriétaire du site à rechercher l'événement dans ses journaux de
sécurité, sous réserve de leur disponibilité.

Une [API officielle de données sportives Stake](https://docs-odds-data.stake.com/)
est documentée avec authentification par clé. Aucun accès ni clé n'est
disponible pour Metiquo à ce jour ; la couverture des marchés League of
Legends, du direct et des suspensions ainsi que les droits d'utilisation
restent à vérifier avec Stake. Aucun basculement automatique vers cette API
n'est activé.
